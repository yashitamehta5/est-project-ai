# Malaria Cell Image Classification (PyTorch CNN)

Classifies single red blood cell images as **Parasitized** (malaria) or **Uninfected**.
The headline model is a small **custom CNN** trained from scratch, as the brief asks. A fine-tuned
**MobileNetV2** is trained as the transfer-learning comparison. Dataset: NIH *Cell Images for Detecting
Malaria* (27,558 PNGs, 50/50). For a full walk-through of the files, how to run them and the report, see
[PROJECT_OVERVIEW.md](PROJECT_OVERVIEW.md).

**Why the custom CNN is the headline model:** it is what the brief asks for, and its ROC-AUC and its
scores at threshold 0.5 are within test-set noise of MobileNetV2 (see the bootstrap table below), and it
is much smaller and faster (ratios in the results block). The trade-off: at the
recall-tuned thresholds, MobileNetV2 gives fewer false alarms for the same recall, so it remains
available as `predict.py --model mobilenet`.

## Quick start (Windows)

1. Double-click **`train_quick.bat`** for a short test run (small subset, 1–2 epochs; results in `outputs\quick\`).
2. Double-click **`train.bat`** for the full training of both models.

On the first run, both launchers create a `.venv` virtual environment and install the requirements.
That includes PyTorch with CUDA 12.8, which the RTX 50-series GPU needs. They don't touch your
global Python. They also run `check_gpu.py` before training.

3. Classify your own images:

```bat
.venv\Scripts\python predict.py path\to\image.png
.venv\Scripts\python predict.py path\to\folder_of_images
.venv\Scripts\python predict.py image.png --model mobilenet
.venv\Scripts\python predict.py image.png --threshold 0.5
```

It prints the label, the confidence and P(Parasitized) for each image. By default it uses the custom CNN
(`outputs\cnn_best.pt`) with its recall-tuned threshold. `--model mobilenet` switches to MobileNetV2, and
`--checkpoint` loads any other saved model file.

4. Open the report notebook: `.venv\Scripts\python -m notebook malaria_cnn.ipynb`
   (use `python -m`: `.venv\Scripts\jupyter` can pick up a global Jupyter and its CPU-only PyTorch).
   In VS Code, select the `.venv` interpreter as the kernel.

## Manual setup

```bat
py -3.11 -m venv .venv
.venv\Scripts\python -m pip install torch==2.11.0+cu128 torchvision==0.26.0+cu128 --index-url https://download.pytorch.org/whl/cu128
.venv\Scripts\python -m pip install -r requirements.txt
.venv\Scripts\python check_gpu.py
.venv\Scripts\python train.py --quick
.venv\Scripts\python train.py
```

`train.py` options: `--model {cnn,transfer,both}`, `--epochs` (CNN, default 50), `--frozen-epochs` (5),
`--ft-epochs` (20), `--patience` (5, early stopping), `--img-size` (128), `--batch-size` (64),
`--lr` (1e-3), `--ft-lr` (1e-4), `--num-workers` (4), `--target-recall` (0.98), `--quick`.

If `check_gpu.py` reports *"no kernel image is available"* or an sm_120 error, the wrong PyTorch build is
installed. Reinstall it from the cu128 index (command above).

## Notes

* Only `cell_images/Parasitized` and `cell_images/Uninfected` are used. `cell_images/cell_images/` is an
  identical copy from the Kaggle zip and is ignored, and so are the `Thumbs.db` files.
* The 70/15/15 stratified split is saved in `outputs/splits/` and reused by every run. A hash check
  confirms that no identical image appears in two splits.
* Only the training DataLoader uses worker processes. On Windows each worker reserves about 2.5 GB of
  virtual memory for PyTorch's CUDA libraries, and 12 workers crashed with *"WinError 1455: the paging
  file is too small"*.
